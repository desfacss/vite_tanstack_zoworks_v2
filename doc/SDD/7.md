## 01_CONSTITUTION.md

```markdown
# Constitution - Immutable Rules

## Database Rules
- **Tenant Isolation**: ALL tables MUST have `organization_id` with RLS enabled
- **Audit Columns**: EVERY table MUST include `created_at`, `updated_at`, `created_by`, `updated_by`
- **No Direct Auth Access**: Client NEVER calls `supabase.auth.admin.*`; ALWAYS use Edge Functions
- **Schema Prefix**: Business logic in `core.*`, tenant data in `crm.*`, `hr.*`, etc.

## Backend Rules
- **Edge Functions**: Used ONLY for auth operations (`invite_users`) or external API calls
- **RPCs**: ALL database write operations go through `core.api_new_*` or `identity.onboard_*` RPCs
- **Testing**: EVERY RPC MUST have SQL test in module's `06_TEST_CASES.md`

## Frontend Rules
- **Dynamic Forms**: Use `DynamicForm`/`RJSFCoreForm` for ALL CRUD unless custom UI required
- **Custom Forms**: MUST register in `src/core/registry.ts` with component path
- **Config Over Code**: Form changes go to `core.forms` table, NOT component code

## Change Management
- **Spec Anchored**: NEVER edit code directly; ALWAYS update SDD first
- **Change Tracking**: ALL modifications go in `07_CHANGE_LOG.md` with OLD vs NEW format
- **Agent Instruction**: Read `[READY]` files only; ignore `[DRAFT]` and `[ARCHIVED]`
```

## modules/identity/01_BUSINESS_RULES.md

```markdown
# Identity Business Rules

## Organization Lifecycle
1. **Requested**: Created via `onboard_request_zoworks_account` (is_active = false)
2. **Approved**: Admin calls `onboard_promote_to_tenant` (is_active = true)
3. **Provisioned**: Modules, roles, teams auto-created
4. **Suspended**: is_active = false (preserves data)

## User Invitation Rules (from your guide)

### Rule 1: New User Flow
- **Trigger**: Email NOT in `identity.users`
- **Action**: Call Edge Function `invite_users` → creates `auth.users`
- **Result**: Email sent, user in pending state, `password_confirmed = false`

### Rule 2: Existing User Flow  
- **Trigger**: Email EXISTS in `identity.users`
- **Action**: Skip Edge Function, call `onboard_invite_user_to_org` directly
- **Result**: `organization_users` created/activated, NO new email

### Rule 3: Cross-Tenant Mapping
- **When**: User already belongs to Org A, invited to Org B
- **Action**: Create new `organization_users` record for Org B
- **Triggers**: Auto-provision `hr.profiles`, `unified.contacts` for Org B

### Rule 4: Role Inheritance
- **SuperAdmin**: Full access (`permissions = '{"*": true}'`)
- **TeamAdmin**: Manages users within assigned team
- **Member**: View-only for team data

## SQL Constraints
```sql
-- Email must be unique across identity.users
ALTER TABLE identity.users ADD CONSTRAINT users_email_unique UNIQUE (email);

-- One active mapping per organization per user
CREATE UNIQUE INDEX idx_active_org_user ON identity.organization_users (organization_id, user_id) WHERE is_active = true;
```
```

### useInviteUser
**Location**: `src/modules/admin/hooks/useInviteUser.ts`
**Implementation**:
```typescript
export const useInviteUser = () => {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: async (data: InviteUserData) => {
      // Step 1: Check if user exists
      const { data: existingUser } = await supabase
        .from('identity.users')
        .select('id, auth_id')
        .eq('email', data.email)
        .single();
      
      let authId = existingUser?.auth_id;
      
      // Step 2: If new user, call Edge Function
      if (!authId) {
        const { data: inviteData } = await supabase.functions.invoke('invite_users', {
          body: { email: data.email }
        });
        authId = inviteData.id;
      }
      
      // Step 3: Add to organization
      const { data: result } = await supabase.rpc('onboard_invite_user_to_org', {
        p_email: data.email,
        p_first_name: data.firstName,
        p_last_name: data.lastName,
        p_org_id: data.organizationId,
        p_role_id: data.roleId,
        p_team_id: data.teamId,
        p_location_id: data.locationId,
        p_auth_id: authId,
        p_details: data.details
      });
      
      return result;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['users', organizationId] });
    }
  });
};
```

# Change Log - Identity Module

## CHANGE-001: Add Slack Notification on Invite
**Date**: 2026-05-21
**Status**: Proposed
**Affects**: `onboard_invite_user_to_org` RPC

### OLD Behavior
```sql
-- After creating organization_user, returns success
SELECT identity.onboard_invite_user_to_org(...);
-- Returns: {"status": "success"}
```

### NEW Behavior
```sql
-- After creating organization_user, sends Slack webhook
SELECT identity.onboard_invite_user_to_org(...);
-- Returns: {"status": "success", "slack_notified": true}
-- Side effect: POST to webhook URL stored in supabase.secrets
```

### Implementation Tasks
- [ ] Add `net.http_post()` to RPC
- [ ] Store webhook URL in `supabase.secrets` (key: `slack_invite_webhook`)
- [ ] Handle failure gracefully (log but don't rollback)
- [ ] Update `06_TEST_CASES.md` TEST-005 to verify webhook call

### SQL Migration
```sql
CREATE OR REPLACE FUNCTION identity.onboard_invite_user_to_org(...)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  v_webhook_url TEXT;
  v_http_status INT;
BEGIN
  -- ... existing logic ...
  
  -- NEW: Send Slack notification
  SELECT decrypted_secret INTO v_webhook_url 
  FROM supabase.secrets 
  WHERE name = 'slack_invite_webhook';
  
  IF v_webhook_url IS NOT NULL THEN
    SELECT status INTO v_http_status
    FROM net.http_post(
      url := v_webhook_url,
      body := jsonb_build_object('text', format('Invitation sent to %s for org %s', p_email, p_org_id))
    );
    
    -- Log but don't fail
    IF v_http_status != 200 THEN
      RAISE LOG 'Slack webhook failed for invite %: %', p_email, v_http_status;
    END IF;
  END IF;
  
  RETURN jsonb_build_object('status', 'success', 'slack_notified', v_http_status = 200);
END;
$$;
```

CREATE OR REPLACE FUNCTION schema_name.function_name(

  p_param2 TYPE DEFAULT NULL

RETURNS JSONB

SECURITY DEFINER
SET search_path = public, core, identity
AS $$
DECLARE
  v_current_user_id UUID;
  v_result JSONB;
BEGIN
  -- 1. Get current user from auth
  v_current_user_id := auth.uid();
  
  -- 2. Validate permissions

EXCEPTION
