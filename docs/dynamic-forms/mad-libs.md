
MAD LIBS FORMS TOGGLE WITH RJSF FORMS


Designing a zero-code onboarding flow for an Active System of Intelligence requires hiding the database schema completely. For high-ticket service operations, the business owner needs to feel like they are instructing an expert, not configuring a database.

Here is how to design the UI components and user experience for establishing the deterministic baseline, heavily leveraging modern React patterns and the TanStack ecosystem.

## 1. The Generative Paradigm: The "Subway Map" UI

When the AI translates the unstructured "Process Mastery" interview into a deterministic baseline, presenting a sprawling, 2D Directed Acyclic Graph (DAG) is overwhelming. We flatten it.

* **Visual Architecture:** Render the workflow as a horizontal, linear "subway line" using an optimized data grid or a custom SVG component. Each major state transition (e.g., *Lead ➡️ Site Inspection ➡️ Quoting ➡️ Contract ➡️ Execution*) is a distinct "station."
* **Interaction Model:**
* The primary line represents the "happy path."
* Alternative routes (e.g., *Quote Rejected*) branch off below the main line but immediately attempt to merge back (e.g., *Follow-up Drip ➡️ Re-Quoting*).


* **Component Strategy:** Avoid heavy drag-and-drop canvas libraries for the core view. A linear, flex-based React component with animated SVG connecting lines keeps the DOM light and the mental model simple.

## 2. The Blueprint Editor: "Mad Libs" Configuration

When a user clicks a station on the Subway Map to adjust SLAs or rules, do not show them a standard form with labels and input boxes. Use a natural language "Mad Libs" interface.

* **The Translation:** You are mapping to a strict `JSONB` payload in PostgreSQL, but the UI reads like a sentence.
* **The UX Pattern:**
* Text is rendered as standard typography.
* Variables are rendered as bold, inline dropdown menus or popovers (using an Ant Design `Select` or `Cascader` component styled to look like clickable text).


* **Example State:** *"If the project is stuck in [**Quoting**] for more than [**48 Hours**], then the system will trigger [**WhatsApp Drip: 'Gentle Nudge'**]."*
* **Why it works:** It forces the configuration to remain human-readable. The user cannot accidentally create a logically broken rule because the sentence structure strictly limits their input combinations.

## 3. The Guardrail UX: Real-Time Validation

Because Vertical Workflow Automation directly controls physical service delivery, a misconfigured SLA can cause real-world chaos (e.g., dispatching a technician to a site without a signed contract). The UI must validate state changes instantly.

* **Optimistic Validation:** Use TanStack Query to perform background validation against the global template schema as the user interacts with the Mad Libs editor.
* **Soft Friction Indicators:**
* If a rule creates a dead end (e.g., a WhatsApp message is sent, but no timeout SLA is set for a non-response), the node on the Subway Map pulses with a soft yellow warning.
* Hovering over the warning reveals a contextual tooltip generated by the AI: *"You send a quote here, but what happens if the client doesn't reply?"*


* **Hard Blocks:** If a required constraint is missing (e.g., bypassing a mandatory digital signature), the "Publish" button disables, and the missing link glows red.

## 4. Simulating the Baseline: The Split-Screen Dry Run

Before deploying the blueprint into the messy reality of SME operations, the user needs absolute confidence that the `ai_mcp.agents` and deterministic rules interact correctly.

* **The Layout:** A dual-pane dashboard view.
* **Left Pane (The Zero-UI Input):** A mock WhatsApp chat interface. The user acts as their own client, typing messages or uploading mock voice notes.
* **Right Pane (The Engine Room):** The newly built execution timeline (your unified ledger).


* **The Execution:** As the user sends a message on the left (e.g., *"I need an HVAC quote, budget is around 2 Lakhs"*), they watch the right pane react in real-time.
* **Visualizing the Loop:** They see the AI Agent block spin as it extracts the budget entity, followed immediately by the deterministic SLA block sliding into place, proving that the system successfully caught the unstructured input and routed it into the structured track.










WITH RJSF FORMS 
Yes, you can absolutely do this. In fact, leveraging your existing `core.forms` and RJSF (React JSON Schema Form) architecture is the most robust way to build this.

You already have the hardest part solved: the `dataSchema` representing the strict PostgreSQL JSONB contract. To toggle between a standard form and a Mad Libs UI, you do not need to change your data state or your schemas; you only need to dynamically swap the **`uiSchema`** and the **custom templates** passed to the RJSF engine.

Here is the architectural pattern to map RJSF to a Mad Libs UI while keeping the toggle seamless.

### 1. The `dataSchema` Remains Untouched

Your JSON Schema remains the absolute source of truth. It defines the payload that your `ai_mcp.agents` and deterministic edge functions will consume.

```json
// This drives BOTH the standard form and the Mad Libs UI
{
  "type": "object",
  "properties": {
    "trigger_state": { "type": "string", "enum": ["Quoting", "Site Inspection"] },
    "sla_hours": { "type": "integer", "enum": [24, 48, 72] },
    "action_id": { "type": "string", "enum": ["drip_nudge", "alert_manager"] }
  }
}

```

### 2. Injecting the Sentence Structure via `uiSchema`

To make RJSF render a sentence, you use the `uiSchema` to pass the static text strings that should appear *before* and *after* the data fields. You define two separate `uiSchema` objects in your codebase.

**Standard `uiSchema`:**

```json
{
  "ui:order": ["trigger_state", "sla_hours", "action_id"]
}

```

**Mad Libs `uiSchema`:**

```json
{
  "ui:ObjectFieldTemplate": "MadLibsTemplate",
  "trigger_state": {
    "ui:widget": "InlineSelectWidget",
    "ui:options": { "prefixText": "If the project is stuck in" }
  },
  "sla_hours": {
    "ui:widget": "InlineSelectWidget",
    "ui:options": { "prefixText": "for more than" }
  },
  "action_id": {
    "ui:widget": "InlineSelectWidget",
    "ui:options": { "prefixText": ", then the system will", "suffixText": "." }
  }
}

```

### 3. Overriding RJSF Templates for Inline Rendering

By default, RJSF's `ObjectFieldTemplate` renders children in vertical stacks with standard `<label>` tags. For the Mad Libs mode, you inject a custom template that strips the standard grid and forces everything into an inline text flow.

```tsx
// 1. The custom widget that renders as a clickable word instead of a box
const InlineSelectWidget = (props) => {
  const { options, value, onChange, schema } = props;
  const { prefixText, suffixText } = options;

  return (
    <span className="inline-flex items-baseline whitespace-pre-wrap text-lg">
      {prefixText && <span>{prefixText} </span>}
      
      {/* Ant Design Select styled to look like inline text */}
      <Select 
        value={value} 
        onChange={onChange}
        variant="borderless"
        className="font-bold text-blue-600 underline decoration-dashed mx-1"
        options={schema.enum.map(e => ({ label: e, value: e }))}
      />
      
      {suffixText && <span> {suffixText}</span>}
    </span>
  );
};

// 2. The custom template that strips the vertical layout
const MadLibsObjectTemplate = (props) => {
  return (
    <div className="leading-loose text-gray-800">
      {/* Renders all fields consecutively in a text block */}
      {props.properties.map(element => element.content)}
    </div>
  );
};

```

### 4. The Toggle Mechanism

Because RJSF is completely controlled by props, toggling between the two views is just a matter of changing the `uiSchema` and the `widgets`/`templates` mappings based on a simple React state.

```tsx
const BlueprintEditor = ({ dataSchema, formData, onChange }) => {
  const [isMadLibsMode, setIsMadLibsMode] = useState(true);

  // Dynamically select the UI configuration
  const activeUiSchema = isMadLibsMode ? madLibsUiSchema : standardUiSchema;
  
  const activeTemplates = isMadLibsMode 
    ? { ObjectFieldTemplate: MadLibsObjectTemplate } 
    : {}; // Fallback to standard RJSF templates

  const activeWidgets = isMadLibsMode 
    ? { InlineSelectWidget: InlineSelectWidget } 
    : {};

  return (
    <div className="blueprint-container">
      <div className="toolbar">
        <Switch 
          checked={isMadLibsMode} 
          onChange={setIsMadLibsMode} 
          checkedChildren="Mad Libs" 
          unCheckedChildren="Standard Form" 
        />
      </div>
      
      <Form
        schema={dataSchema}
        uiSchema={activeUiSchema}
        formData={formData}
        onChange={e => onChange(e.formData)}
        widgets={activeWidgets}
        templates={activeTemplates}
        validator={validator}
      />
    </div>
  );
};

```

**Why this is the perfect architecture:**

* **Zero State Duplication:** RJSF handles the complex `onChange` events, validation, and JSONB generation natively.
* **Fallback Safety:** If an operations manager is dealing with a highly complex edge case where the Mad Libs sentence becomes too convoluted, they just flip the toggle. The UI instantly reverts to the standard vertical form they recognize, allowing them to fill out the raw variables, and then they can flip it back.
* **Extensibility:** When you push global template updates to your multi-tenant database, you are just pushing new JSON schemas. Both UI modes automatically inherit the new fields without you having to write new React components.
